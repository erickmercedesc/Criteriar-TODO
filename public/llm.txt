# SecondBrain API - Guía para LLMs / Bots

Bienvenido al sistema SecondBrain. Este archivo contiene las instrucciones necesarias para interactuar con la API REST de esta aplicación.

## Funcionamiento General
SecondBrain es una aplicación de gestión de tareas gamificada (desarrollada con Laravel, Inertia y Vue PWA). Su objetivo principal es ayudar a los usuarios a organizar su día a día recompensándolos por completar tareas.
Los usuarios pueden crear Proyectos para agrupar sus tareas. Al trabajar, pueden elegir un contexto "Global" (todas las tareas) o enfocarse en un Proyecto específico.
Los usuarios pueden crear tareas (TODOs) y asignarles "Criterios de Puntuación" (Scoring Criteria) y opcionalmente a un Proyecto. Cada criterio tiene un valor en puntos (positivos o negativos). 
Al completar una tarea, el usuario suma los puntos totales de la tarea a sus estadísticas diarias, fomentando la productividad a través de la gamificación. El sistema también permite marcar ciertos criterios como "complejos" para ayudar al usuario (o a un agente planificador) a equilibrar su carga de trabajo y evitar la fatiga.

## Autenticación
La API requiere un token de acceso (Bearer Token).
Debes enviar el token en la cabecera HTTP de todas tus peticiones:
`Authorization: Bearer <tu_api_token>`

## Endpoints Principales

La API base se encuentra en `/api`. Todas las respuestas son en formato JSON.

### Tareas (TODOs)
Las tareas son elementos a realizar que pueden pertenecer a un proyecto y tener uno o más "criterios" asignados. El sistema calcula automáticamente un puntaje (`total_score`) basado en la suma de los puntos de los criterios.

- `GET /api/tasks` : Obtener todas las tareas. Parámetros query opcionales: `?completed=1/0`, `?project_id=1`, `?criteria_ids=1,2,3`, `?min_score=10`, `?max_score=50`.
- `GET /api/tasks/top` : Obtener las top 3 tareas pendientes con mayor puntuación para hoy. Parámetro query opcional: `?project_id=1`.
- `POST /api/tasks` : Crear una tarea.
  - Body: `{"title": "string", "notes": "string|null", "project_id": integer|null, "criteria_ids": [1, 2]}`
- `GET /api/tasks/{id}` : Ver detalle de una tarea.
- `PUT /api/tasks/{id}` : Actualizar una tarea (marcar como completada o cambiar proyecto/notas).
  - Body: `{"title": "string", "notes": "string|null", "is_completed": boolean, "project_id": integer|null, "criteria_ids": [1, 2]}`
- `DELETE /api/tasks/{id}` : Eliminar una tarea.

### Proyectos (Projects)
Los proyectos sirven para agrupar tareas. Los usuarios pueden filtrar sus tareas por proyecto.

- `GET /api/projects` : Obtener todos los proyectos.
- `POST /api/projects` : Crear un proyecto.
  - Body: `{"name": "string", "color": "#hex|null", "criteria_ids": [1, 2]}`
- `GET /api/projects/{id}` : Ver detalle de un proyecto.
- `PUT /api/projects/{id}` : Actualizar un proyecto.
  - Body: `{"name": "string", "color": "#hex|null", "criteria_ids": [1, 2]}`
- `DELETE /api/projects/{id}` : Eliminar un proyecto.

### Criterios de Puntuación (Scoring Criteria)
Los criterios son etiquetas configurables que otorgan puntos (positivos o negativos) a las tareas a las que son asignados.

- `GET /api/scoring-criteria` : Obtener todos los criterios disponibles.
- `POST /api/scoring-criteria` : Crear un criterio.
  - Body: `{"name": "string", "points": integer, "color": "#hex", "is_complex_marker": boolean}`
- `GET /api/scoring-criteria/{id}` : Ver detalle de un criterio.
- `PUT /api/scoring-criteria/{id}` : Actualizar un criterio.
- `DELETE /api/scoring-criteria/{id}` : Eliminar un criterio.

## OpenAPI / Swagger
Para obtener la especificación OpenAPI (Swagger) completa y dinámica en formato JSON, haz una petición GET a:
`/docs/api-docs.json` (o la ruta por defecto de Swagger `/api/documentation`).

## Reglas de Negocio a tener en cuenta:
1. **Completar una Tarea**: Si envías `is_completed: true` en un PUT a una tarea, el sistema automáticamente actualizará las estadísticas diarias del usuario sumándole el puntaje total de esa tarea.
2. **Tareas Complejas**: Criterios con `is_complex_marker = true` indican que la tarea toma mucho tiempo y puede generar fatiga. Si actúas como un agente planificador, prioriza intercalar tareas complejas con tareas sencillas.
3. **Manejo de Errores**: Si omites un campo requerido, la API responderá con un código HTTP `422 Unprocessable Entity` y un JSON detallando los errores de validación.
